# Photon64 v1.0.0-preview.2

This preview focuses on preserving progress, reliable renderer transitions and a reproducible release artifact. Download **photon64.html** from the assets and open it in a modern browser with WebAssembly SIMD support. Add your own cartridge dump or ZIP.

## Changes

- Reset and state restoration preserve the obligation to save battery progress. Failed transactions keep progress in memory and expose retry/export recovery.
- Full-content cartridge identities distinguish patches and revisions. Verified legacy migration preserves originals; ambiguous entries require manual battery import. Faster later selections cannot be replaced by an obsolete file read.
- Circular GPU memory ownership, scale-request ordering, partial allocation cleanup and asynchronous validation/device-loss handling have targeted fixes. Diagnostics include the first cause, renderer generation, full core identity, adapter and bounded event history.
- Correct original addresses for merge-load faults, segment privilege checks, unsigned byte packing and the missing CIC 6105 challenge response. CIC tests compare a pinned independent implementation; hardware protocol and protected-game certification remain open.
- Four browser gamepad ports, audio initialization retry/cleanup, accessible sibling library controls, exclusive cartridge writers and storage usage. Save-hardware override has a recoverable backup; portable battery/state files validate metadata.
- Actual-size reusable cartridge allocation, count-only state-slot metadata reads and bounded readback resources reduce avoidable memory use. Frame/GPU/audio counters support further device profiling.
- Required real software-adapter GPU validation, standalone file-origin tests, explicit nine-job release gates and bounded native Safari journaling with five full sequences.

## Upgrading and recovery

Export battery progress before replacing the HTML. States depend on the exact WASM core and cannot be moved across incompatible builds. Loading a state restores its battery data and creates a fresh persistence obligation. New portable battery files carry cartridge metadata; legacy raw battery files remain accepted.

Cartridge keys now use canonical content SHA-256. Automatic migration requires matching cached cartridge bytes and retains originals. If old cache bytes are absent or ambiguous, use the previous app to export its battery file, then import it into the selected cartridge. See [migration and recovery](https://github.com/PowerBeef/Photon64/blob/main/MIGRATION.md).

Unsupported cross-tab arbitration uses temporary progress with export. File-origin storage and GPU access depend on browser policy; localhost remains an option. On GPU loss, export battery progress and reset or reopen. No transparent recovery of GPU-only machine state is claimed.

## Exact validation and limits

This is the exact HTML artifact from [successful validation run 38087805779](https://github.com/PowerBeef/Photon64/actions/runs/38087805779), built at `1e8c2ea4019a152db0c17dc77ae77ef7a1bf4e38`. All nine named jobs passed: baseline, actual software-adapter GPU, native macOS Safari and six Chromium/Chrome/Edge/WebKit desktop/mobile-emulated variants. Safari passed desktop-alone and five complete narrow/landscape/desktop sequences. The tested HTML is 462,470 bytes.

Native and full-storage HD-at-1x GPU vectors, deliberate device loss and 180-field authored drawing/state/reset sequences pass on a Mesa software Vulkan adapter. Those results establish tested shader/coherence behavior, not physical GPU speed. The baseline includes sanitizer and identical O0/O3 WASM checks plus independent raw/VI comparisons.

Photon64 remains experimental. Physical iOS/Android, native filesystem choosers, audio output, real controllers and VoiceOver still need device tests. Hosted Safari uses a browser-backed File because the native OS-backed read probe fails independently on that runner. Browser file-origin GPU coverage explicitly reports SKIP when no adapter is available.

The RDP installed-RAM boundary model still disagrees with the pinned reference; the failing diagnostic is retained separately. CPU effective addresses remain 32-bit, CACHE has no cache model, and timing uses constant CPI. Broader hardware FPU/CIC/renderer expectations, dependency-safe scheduling optimization and parts of upstream fixture provenance remain open. See [capabilities](https://github.com/PowerBeef/Photon64/blob/main/CAPABILITIES.md), the [implementation report](https://github.com/PowerBeef/Photon64/blob/main/reports/implementation-2026-10-10/REPORT.md) and third-party notes.

`SHA256SUMS` and `build-info.json` record asset hashes, source and validation run. `tested-build-info.json` identifies the tested HTML/WASM; the workflow verifies the embedded WASM against that artifact. Required licenses/notices come from the selected source revision and are also embedded where applicable.
